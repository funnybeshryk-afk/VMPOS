## Что умеет сейчас (линия релизов)
Продажа (сканер, поиск, корзина, оптовые цены, смешанная оплата, долги), возвраты, смены и Z-отчёт, склад и приход,
поставщики, клиенты, пользователи/роли, отчёты, печать этикеток (Code128), резервные копии, авто-обновление.

## Что есть только в `receipt-print-merged`
- Схема v2: ИКПУ, код упаковки, НДС по строкам (снимок на момент продажи), статусы фискализации (`docs/FISCAL.md`).
- Печать чека без фискальных реквизитов: термопринтер через драйвер Windows или PDF, 58/80 мм, предпросмотр.
- Статус-бар: Printer — реальная проверка (Tayyor / Topilmadi / PDF), Skaner — время последнего настоящего скана. Весы убраны (нет поддержки).

2. Имя кассира на чеке (сейчас нет).
3. **Выпуск схемы v2** — старые версии не откроют новую базу (`DatabaseTooNewError`): решить, когда обновляем все кассы разом.
4. Фискальная интеграция (провайдер не выбран; «боевую базу — потом»).
5. Возможно EAN-13 для внутренних 13-значных кодов (сейчас Code128; контрольные цифры не валидны — смена символики поменяет сохранённые коды).
6. Просмотр с телефона / веб-версия — отложено (решение владельца: сначала довести десктоп).
7. «Напомни позже» — владелец не назвал тему и время, напоминание **не поставлено**.

## Решения владельца (не пересматривать)
- Остаёмся на **exe + Widgets** (QML и веб отвергнуты). Тач — ко всем окнам, отдельной экранной клавиатуры нет.
- Акцент **изумрудный** (янтарь занят другим проектом).
- Один магазин, интернет есть; цель — приятный интерфейс, надёжное обновление, живой тест в магазине.

## Известные ограничения
- Тесты на реальном принтере/сканере/Windows-установщике из облачной сессии не гоняются.
- Теги из сессии не пушатся → релиз только через workflow_dispatch.
